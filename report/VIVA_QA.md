# Viva Examination Preparation Guide — MiniSQL Query Compiler

---

## Part 1: High-Level Architecture & Concepts

### Q1: What makes MiniSQL a real compiler rather than an interpreter?
**Answer**:
An interpreter directly evaluates the AST while traversing it. MiniSQL is a compiler because it translates source SQL statements through intermediate representations (Relational Algebra Tree and Three-Address Code) and lowers them into a target bytecode format (`BytecodeProgram`). The generated bytecode is subsequently executed by a separate stack-based Virtual Machine (`vm.py`).

### Q2: What are the seven phases of the MiniSQL compiler?
**Answer**:
1. **Lexical Analysis (`lexer.py`)**: Tokenization via DFA scanner.
2. **Syntax Analysis (`parser.py`)**: LL(1) recursive-descent parsing into an AST.
3. **Semantic Analysis (`semantic.py` & `catalog.py`)**: Symbol table lookup, type checking, scoping, and qualification.
4. **IR Generation (`irgen.py` & `ir.py`)**: Translating AST to Relational Algebra Tree & Three-Address Code.
5. **Optimization (`optimizer.py`)**: Transforming IR (constant folding, boolean simplification, predicate pushdown).
6. **Code Generation (`codegen.py`)**: Lowering optimized plan to target VM bytecode instructions.
7. **Virtual Machine Execution (`vm.py` & `storage.py`)**: Executing bytecode on a stack VM against in-memory storage.

## Part 2: Lexer & Parser Questions

### Q3: How does the Lexer handle multi-character operators like `<=`, `>=`, `!=`, `<>`?
**Answer**:
The Lexer inspects a single character lookahead (`self._peek(1)`). If the current character is `<` and the lookahead is `=`, it consumes both characters and emits a single `OPERATOR` token with lexeme `<=` at line and column offsets.

### Q4: What parsing strategy is used in `parser.py`?
**Answer**:
MiniSQL uses an **LL(1) Recursive Descent Parser**. Each non-terminal in the Context-Free Grammar is implemented by a Python method (e.g., `_parse_select()`, `_parse_expr()`). Operator precedence in expressions is enforced by cascading methods (`_parse_or()` -> `_parse_and()` -> `_parse_not()` -> `_parse_comparison()` -> `_parse_add()` -> `_parse_mul()` -> `_parse_primary()`).

### Q5: How does panic-mode error recovery work during parsing?
**Answer**:
When `parser.py` encounters an unexpected token, it records the diagnostic via `ErrorReporter`, raises a private `_SyncError`, and invokes `_synchronize()`. The synchronizer skips incoming tokens until reaching a synchronization token (the semicolon `;` statement terminator), allowing parsing to resume for subsequent statements.

## Part 3: Semantic Analysis & Symbol Table

### Q6: What role does `Catalog` play in compiler design terms?
**Answer**:
The `Catalog` is the compiler's **Symbol Table**. It records table schemas, column data types, primary key flags, and query-local alias bindings. The semantic analyzer queries the Symbol Table to verify column existence, disambiguate unqualified references, and validate type correctness.

### Q7: How does MiniSQL handle aggregate coherence validation in `SELECT` queries?
**Answer**:
When aggregate functions (`COUNT`, `SUM`, `AVG`, `MIN`, `MAX`) appear in a `SELECT` statement with a `GROUP BY` clause, the semantic analyzer enforces the ANSI SQL invariant that every un-aggregated column in the `SELECT` list must explicitly appear in the `GROUP BY` column list.

## Part 4: IR, Optimization & Code Generation

### Q8: What Intermediate Representations (IR) does MiniSQL use?
**Answer**:
MiniSQL utilizes two IR formats:
1. **High-Level IR**: A Relational Algebra Plan Tree (`ScanNode`, `FilterNode`, `ProjectNode`, `JoinNode`, `AggregateNode`).
2. **Low-Level IR**: Three-Address Code (TAC) quadruples of the format `(op, arg1, arg2, result)`.

### Q9: Explain Predicate Pushdown and why it improves query efficiency.
**Answer**:
Predicate Pushdown shifts filter operations (`FilterNode`) down the relational algebra tree so they are evaluated *before* expensive operations like `JoinNode`. Filtering rows early reduces the cardinalities of intermediate relations, decreasing memory bandwidth and comparison operations.

### Q10: How does the virtual machine execute expressions and handle SQL Three-Valued Logic?
**Answer**:
The VM uses an `ExprEvaluator` module that evaluates expression ASTs against current row contexts. It natively implements ANSI SQL Three-Valued Logic where comparison operations involving `NULL` yield `None` (unknown), and `AND`/`OR` short-circuit according to standard SQL truth tables.
